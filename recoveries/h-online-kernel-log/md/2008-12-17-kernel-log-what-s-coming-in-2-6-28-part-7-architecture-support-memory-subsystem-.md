# Kernel Log: What's coming in 2.6.28 - Part 7: architecture support, memory subsystem and virtualisation

**Dj Walker-Morgan**

![](../site/imgs/43/3/6/5/8/2/9/93e8ea3d0acdf147.jpg) It's not just the [audio drivers](../site/news/item/Kernel-Log-What-s-coming-in-2-6-28-Part-6-Changes-to-the-audio-drivers-739369.html "Kernel Log: What's coming in 2.6.28 - Part 6: Changes to the audio drivers – 15 December 2008, 17:53") which have seen important changes during the second half of the development phase for 2.6.28 – there have also been significant developments relating to the various architectures supported by Linux, and in virtualisation technologies and memory management – which is one of the reasons why the Kernel Log is only reporting on these new features in the forthcoming version of Linux now, during the [final phase of 2.6.28 development](../site/news/item/Kernel-Log-New-kernel-versions-progress-with-Btrfs-and-Tux3-739341.html "Kernel Log: New kernel versions, progress with Btrfs and Tux3 – 13 December 2008, 11:07").

After several years of development, the kernel development team has adopted a number of "VM pageout scalability improvements", driven primarily by Rik van Riel, which revamp and optimise parts of the memory subsystem (including [1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=68a22394c286a2daf06ee8d65d8835f738faefa5), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=4f98a2fee8acdb4ac84545df98cccecfd130f8db), [3](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=556adecba110bf5f1db6c6b56416cfab5bcab698), [4](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=7e9cd484204f9e5b316ed35b241abf088d76e0af), [5](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=c5fdae469a6a26cd882d7fe0aa3fbfffb6b72fc5), [6](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=33c120ed2843090e2bd316de1588b8bf8b96cbde), [7](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=ba470de43188cdbff795b5da43a1474523c6c2fb), [8](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=b69408e88bd86b98feb7b9a38fd865e1ddb29827), [9](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=f04e9ebbe4909f9a41efd55149bc353299f4e83b), [10](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=894bc310419ac95f4fa4142dc364401a7e607f65), [11](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=7b854121eb3e5ba0241882ff939e2c485228c9c5), [12](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=e0f79b8f1f3394bb344b7b83d6f121ac2af327de)). This is intended to reduce the administrative overhead for memory-intensive applications and for systems with large amounts of RAM. Details and background on the changes can be found in an [LWN.net article](http://lwn.net/Articles/286472/). A number of changes introduced by Nick Piggin will also specifically reduce the CPU load arising from memory management (including [1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=62695a84eb8f2e718bf4dfb21700afaa7a08e0ea), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=b291f000393f5a0b679012b39d79fbc85c018233), [3](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=5344b7e648980cc2ca613ec03a56a8222ff48820), [4](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=f45840b5c128445da70e7ec33adc47b4a12bdaf4), [5](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=a978d6f521063514812a7094dbe5036e056e4de3), [6](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=db64fe02258f1507e13fe5212a989922323685ce)) – LWN.net also has [background information](http://lwn.net/Articles/304188/) on this.

With the include files for ARM, IA64, Power and Sparc having migrated from include/*xyz* to arch/*xyz*/include in [Linux 2.6.27](http://www.heise-online.co.uk/open/Kernel-Log-Linux-2-6-27-Released--/features/111671/4), the files for a number of other architectures, including [MIPS](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=384740dc49ea651ba350704d13ff6be9976e37fe) and [x86](http://git.kernel.org/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=bb8985586b7a906e116db835c64773b7a7d51663), are now following suit in 2.6.28. The kernel development team have also overhauled APIC support for x86 systems in various places and extended it to include support for [x2apic](http://download.intel.com/design/processor/specupdt/318148.pdf)![PDF](../site/icons/file-pdf.gif "PDF document") (including [1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=6e1cb38a2aef7680975e71f23de187859ee8b158), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=2ae21010694e56461a63bfc80e960090ce0a5ed9), [3](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=89027d35aa5b8f45ce0f7fa0911db85b46563da0), [4](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=e61d98d8dad0048619bb138b0ff996422ffae53b)). [One new feature](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=dc1e35c6e95e8923cf1d3510438b63c600fee1e2) is support for the XSAVE and XRSTOR commands, supported by newer Intel processors, which save or restore the state of x87 and SSE registers during context switches. Following a redesign, apparently driven by AMD, Microcode Loader, which previously only allowed Intel CPU microcode to be updated, now supports newer AMD processors (e.g. [1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=a0a29b62a9cac6b7d83b7514679f2ed8d33d4372), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=d45de40934897c6ee5b05141f7895bbb28512395), [3](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=80cc9f1020f49c9e5b50898c102fd444de70a0a3)). There have also been a number of fundamental changes relating to performance and code debugging, including [kernel tracepoints](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=97e1c18e8d17bd87e1e383b2e9d9fc740332c8e2) ([documentation](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=24b8d831d56aac7907752d22d2aba5d8127db6f6), [examples](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=4a0897526bbc5c6ac0df80b16b8c60339e717ae2)) and the [unified trace buffer](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=7a8e76a3829f1067b70f715771ff88baf2fbf3c3). The kernel development team have [removed](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=8b8e8c1bf7275eca859fe551dfa484134eaf013b) irqbalance – in most distributions the eponymous userspace demon has already been taking care of this for several years.

As [in Linux 2.6.27](http://www.heise-online.co.uk/open/Kernel-Log-Linux-2-6-27-Released--/features/111671/2#firmware), the development team has once again eliminated numerous calls to the Big Kernel Lock (BKL), used for safeguarding critical code regions during multiprocessor operation, or transferred them from the driver subsystem to the drivers themselves. The kernel coders have also pushed forward with consolidation of the directories and source code files for support for x86-32 and x86-64 systems, which started in Linux 2.6.24. This time around, this ongoing process has included various areas of code relating to IRQ management. This should result in further convergence of the behaviour of the 32 and 64 bit kernels, which previously differed somewhat in the way they dealt with IRQ configuration.

2.6.28 also includes a number of new features for virtualisation solutions. Under the KVM virtualisation solution it is now possible to pass PCI devices through to guests, with the help of Intel's VT-D (e.g. [1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=4d5c5d0fe89c921336b95f5e7e4f529a9df92f53), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=62c476c7c7f25a5b245b9902a935636e6316e58c), [3](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=387179464257921eb9aa3d15cc3ff194f6945a7c)). [Improvements](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=20754c2495a791b5b429c0da63394c86ade978e7) have also been made which should allow operating systems running as KVM guests to start up around 15 per cent faster. The kernel now offers a [Container Freezer](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=dc52ddc0e6f45b04780b26fc0813509f8e798c42) for container-based visualisation, which allows a container to be frozen completely ([documentation](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=bde5ab65581a63e9f4f4bacfae8f201d04d25bed)), allowing, for example, a low priority cluster job to be temporarily suspended. The kernel code for operating as a Xen guest system (DomU) [now also allows](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=d68d82afd4c88e25763b23cd9cd4974573a3706f) CPU hotplugging. Xen DomU and IOMMU support for Intel's Itanium (IA64) has also been added. The Xen code to run a primary Xen domain (Dom0) has, as expected, not made it into 2.6.28.
