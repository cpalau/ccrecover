# Kernel Log: Linus resolves to apply a strict policy over merging changes

**Thorsten Leemhuis**

**It would appear that Linus Torvalds has resolved to apply a strict policy of accepting only bug fix changes to the kernel after the merge window has closed. Torvalds has also stuck his oar into the debate over the Android suspend block API and made the situation even more complicated.**

For years, major changes for each new Linux kernel version have been merged into the main development tree during the merge window, which usually lasts about two weeks and concludes with the release of the first pre-release version of the next kernel (2.6.*x*-rc1). Thereafter, changes are theoretically restricted to patches which fix existing bugs without giving rise to new ones. In practice, RC2 and RC3 have included the odd major change and some clean up work, such as resolving compiler warnings, has found its way in at an even later stage.

This was certainly the case for kernel version 2.6.35, the [second pre-release version](http://thread.gmane.org/gmane.linux.kernel/995574) included a number of changes which were anything but negligible. However, on releasing that version, Torvalds hinted that from now on he would only accept changes which resolved bugs. Various emails from Torvalds on LKML over the following days, in which he firmly rejected a number of git pull requests and asked subsystem maintainers to submit only bug fixes, show that he means this to be taken seriously (e. g. [1](http://thread.gmane.org/gmane.linux.kernel/995992/focus%3D996041), [2](http://thread.gmane.org/gmane.linux.kernel/995791/focus%3D996043), [3](http://thread.gmane.org/gmane.linux.kernel/995574/focus%3D996073), [4](http://thread.gmane.org/gmane.linux.kernel/995791/focus%3D46749), [5](http://thread.gmane.org/gmane.linux.kernel/995791/focus%3D996133), [6](http://thread.gmane.org/gmane.linux.drivers.platform.x86.devel/216/focus%3D217), [7](http://thread.gmane.org/gmane.linux.kernel/996619/focus%3D996628), [8](http://thread.gmane.org/gmane.linux.kernel.pci/8901/focus%3D8902), [9](http://thread.gmane.org/gmane.linux.kernel/997784/focus%3D997787)). Even some minor, supposedly risk-free clean up work [has been rejected](http://thread.gmane.org/gmane.linux.kernel/997784/focus%3D997796).

One reason for this change of approach appears to be a [bug](http://git.kernel.org/linus/386f40c86d6c8d5b717ef20620af1a750d0dacb4) in RC2 caused by an apparently innocuous change which resulted in TTY subsystem code overwriting memory pages used by other kernel code – with the result that testers observed a range of poorly reproducible problems in various parts of the kernel. The second reason for tightening up the procedure is more prosaic – Torvalds went on holiday following the [release of RC3](http://thread.gmane.org/gmane.linux.kernel/997936) and was keen to leave testers with as sound a kernel as possible. This is unlikely to be a one-off, as Torvalds has indicated in a number of emails that in future he intends to be strict about only merging bug fixes into the main development tree after the merge window has closed. How fastidious he will be in practice will become apparent over the next few months.

### Linux version status

The most recent of Rafael J. Wysocki's roughly weekly regression reports lists 26 bugs [in Linux 2.6.35-rc3](http://thread.gmane.org/gmane.linux.kernel.kernel-testers/9456) which were not present in 2.6.34 – the latest pre-release version of 2.6.35 also still contains [28 bugs](http://thread.gmane.org/gmane.linux.acpi.devel/46396) which appeared during Linux 2.6.34 development.

Only one new stable kernel, [Linux 2.6.32.15](http://article.gmane.org/gmane.linux.kernel/993378/) has been released since the [last Kernel Log](../site/open/features/Kernel-Log-Linux-2-6-35-taking-shape-1012850.html "Kernel Log: Linux 2.6.35 taking shape – 01 June 2010"). It contains just two changes which fix bugs in the previous version – users using the latter without having experienced problems do not need to upgrade.

### In Brief

*Kernel*

- The debate over the suspend block API (formerly Wakelocks) developed by Google for Android (covered in the [last Kernel Log](../site/open/features/Kernel-Log-Linux-2-6-35-taking-shape-1012850.html "Kernel Log: Linux 2.6.35 taking shape – 01 June 2010")) continued for a further few days. Linus Torvalds eventually [got involved](http://thread.gmane.org/gmane.linux.kernel/994817/focus%3D994821), criticising a solution proposed by Ingo Molnar. Thanks to this and other objections from Linux' founding father, a rapid solution to the situation looks less likely than ever. A solution involving the addition of some compatibility code to make it much easier to merge Android drivers, which rely on the suspend block API, into the Linux main development tree may be implemented as an interim measure until a better solution can be found. LWN.net has recently published a series of articles detailing the complex issues involved ([1](http://lwn.net/Articles/391245/), [2](http://lwn.net/Articles/390369/)).
- Christoph Hellwig's [XFS Status Update for May 2010](http://thread.gmane.org/gmane.linux.kernel/998997) provides an overview of the latest changes in the XFS file system world.
- Edward Shishkin, who used to work on Reiser4 and is now employed by Red Hat, has discovered a problem in Btrfs when using inline extents. He states that only a major redesign of the file system can resolve the problem and has some harsh words for some of the file system code ([1](http://thread.gmane.org/gmane.linux.kernel/994558), [2](http://thread.gmane.org/gmane.linux.kernel/994558/focus%3D41965)). Btrfs main developer Chris Mason takes a more [relaxed](http://thread.gmane.org/gmane.linux.kernel/994558/focus%3D1000380) view of the problem, Red Hat developer Josef Bacik, who has added a whole host of enhancements to Btrfs in recent months, has not yet responded to the criticism expressed by his colleague.
- The kernel patches for [supporting](http://thread.gmane.org/gmane.linux.ports.arm.kernel/77567/focus%3D82490) NVIDIA's ARM core-based Tegra system-on-a-chip (SOC) family, which are being driven forward by Android developer Erik Gilling, have now been [merged into linux-next](http://thread.gmane.org/gmane.linux.kernel/1000155) and may find their way into Linux 2.6.36.
- James Morris has [released](http://thread.gmane.org/gmane.linux.kernel.cryptoapi/4412/focus%3D4469) the programme for August's Linux Security Summit 2010 and gives a broad outline of the event [on his blog](http://blog.namei.org/2010/06/17/linux-security-summit-2010-boston-schedule-published/).
- Following a [major revamp](http://thread.gmane.org/gmane.linux.drivers.driver-project.devel/6414/), the Ramzswap, formerly Compcache, framework for indirectly compressing areas of memory will be renamed Zram in 2.6.36.
- Valerie Aurora continues to work on developing a union mount solution which is good enough to be merged into the standard kernel ([1](http://valerieaurora.wordpress.com/2010/06/15/union-mounts-update/), [2](http://thread.gmane.org/gmane.linux.kernel/999172)).
- Dell's HPC specialist Jeffrey B. Layton has published [an article](http://www.linux-mag.com/cache/7793/1.html) summarising storage related changes to the Linux kernel over the last year.
- MD and Mdadm developer Neil Brown [is writing code](http://thread.gmane.org/gmane.linux.raid/28294) to improve the way the kernel's MD code handles defective disk sectors on RAID 1. He is also working [on patches](http://thread.gmane.org/gmane.linux.raid/28188) to allow the MD RAID5 code to be used with the device mapper. This will enable a host RAID 5 to be addressed by Dmraid – something which can currently only be achieved using kernel patches which, although they have been around for several years, have never been merged into the official kernel.

*Graphics*

- Peter Hutterer has been particularly active in recent weeks and has recently released [the second](http://thread.gmane.org/gmane.comp.freedesktop.xorg/43797) X-Server version 1.8.2 release candidate. He has also released [a pre-release version](http://thread.gmane.org/gmane.comp.freedesktop.xorg.announce/1070) of the xf86-input-synaptics 1.3.0 X.org touchpad driver which utilises a different acceleration detection metric. Details can be found [on his blog](http://who-t.blogspot.com/2010/06/new-synaptics-acceleration-mechanism.html), where he has also recently posted a [detailed explanation](http://who-t.blogspot.com/2010/06/incomplete-roundup-of-touchpad-features.html) of the functionality offered by the touchpad driver, including edge scrolling, two finger scrolling, multi-finger tapping and circular scrolling. He also reports on new [standard procedures](http://who-t.blogspot.com/2010/06/new-evdev-middle-mouse-button-emulation.html) for emulating the middle mouse button.
- Keith Packard has released the first pre-release version of [X-Server 1.9](http://thread.gmane.org/gmane.comp.freedesktop.xorg/43773), which is scheduled for release in late August. [As](http://thread.gmane.org/gmane.comp.freedesktop.xorg.devel/9422) the Linux kernel development is at the end of the merge window, development of the next major X Server revision now enters a stabilisation phase. Packard stresses that the next version of X Server will not include a lot of new functionality, but will resolve many long-standing issues and make the code cleaner and easier to understand.
- \*AMD has released version 10.6 of its Fglrx (aka Catalyst) [Linux graphics driver](http://support.amd.com/us/gpudownload/Pages/index.aspx). It includes official support for OpenGL 4.0 on Radeon HD 5000 series graphics cards and for OpenGL 3.3 on older Radeon HD graphics hardware. A "new architecture for 2D acceleration" should improve 2D performance and, among other things, accelerate adjustment to window size. Red Hat Enterprise Linux 5.5 also becomes a fully supported operating system. Further details of the changes can be found in the [release notes](http://www2.ati.com/drivers/linux/catalyst_106_linux.pdf)![PDF](../site/icons/file-pdf.gif "PDF document") for the new version.
- The [new version](http://lists.x.org/archives/xorg-driver-ati/2010-June/016047.html) of the [R5xx 3D Programming Guide](http://www.x.org/docs/AMD/R5xx_Acceleration_v1.5.pdf)![PDF](../site/icons/file-pdf.gif "PDF document") offers more detail in some areas than the previous version.
- The [Mesa development team](http://mesa3d.org/) has [released](http://thread.gmane.org/gmane.comp.video.mesa3d.announce/99) version 7.8.2 of Mesa 3D. This follows Intel developer Eric Anholt's release of [libdrm 2.4.21](http://thread.gmane.org/gmane.comp.video.dri.devel/46855).
- The release of [version 256.35](http://www.nvnews.net/vbulletin/showthread.php?p=2273450) as a release candidate means that the main development phase for NVIDIA's 256 series graphics driver is drawing to a close.
- Intel has [released](http://lists.freedesktop.org/archives/intel-gfx/2010-June/007129.html) the first release candidate of the intel 2.12 X.org graphics driver. The release email stresses numerous performance enhancements, which should improve scroll speed in Firefox.
- Intel intends to [stop supporting its ipw2*x*00](http://thread.gmane.org/gmane.linux.kernel.wireless.general/52022/) WLAN drivers, a move which has come in for criticism from, among others, kernel developer [David Miller](http://thread.gmane.org/gmane.linux.kernel.wireless.general/52022/focus%3D52104), as Intel's failure to release documentation for the WLAN chips supported by the drivers makes driver maintenance very difficult.

*Kernel plumbing layer, userland drivers, developer tools*

- Karel Zak has released a pre-release version of util-linux-ng 2.18. His release email for the [first](http://thread.gmane.org/gmane.linux.utilities.util-linux-ng/3241) of [two](http://thread.gmane.org/gmane.linux.kernel/1000337) release candidates lists numerous changes, and in future the tool collection, which is used by all the mainstream distributions, will include the findmnt, fsfreeze and swaplabel programs and the libmount library. The ramsize, rdev, rootflags and vidmode commands have been removed.
- Lennart Poettering has made his LinuxTag [presentation](http://0pointer.de/public/systemd-presentation-linuxtag2010.pdf)![PDF](../site/icons/file-pdf.gif "PDF document") on systemd, an alternative to Initrd and Upstart, available [online](http://0pointer.de/blog/projects/linuxtag-2010-slides.html).
- [On his blog](http://www.j5live.com/2010/06/09/multitouch-working-in-fedora/), GNOME developer John (J5) Palmieri reports on progress in multitouch support in X.org and the GTK toolkit.
- Jon Masters has [released module-init-tools v3.12](http://thread.gmane.org/gmane.linux.kernel.modules/476), the major changes in which are [listed on the wiki](https://modules.wiki.kernel.org/index.php/Module_init_tools_3_12). Softdeps should improve modprobe's handling of implicit dependencies; the new version also supports [devnames](http://git.kernel.org/linus/578454ff7eab61d13a26b568f99a89a2c9edc881), introduced in Linux 2.6.35, which allow udev to automatically load some modules, for which the standard loading automation did not previously work, when a device node is accessed.
- Earlier this month, Kay Sievers released [udev version 157](http://thread.gmane.org/gmane.linux.hotplug.devel/15811), which is primarily a bug fix release.
