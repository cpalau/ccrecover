# Kernel Log: First release candidate concludes the hot development phase of 2.6.27

**Dj Walker-Morgan**

![](../site/imgs/43/3/6/3/4/6/8/93e8ea3d0acdf147.jpg) With the release of [Linux 2.6.27-rc1](http://thread.gmane.org/gmane.linux.kernel/713115), Linus Torvalds has concluded the first phase (merge window) of the current development cycle and has integrated all the major changes for Linux version 2.6.27, which is expected for release towards the end of September. Therefore, all major improvements of the next kernel version are now already included in the [source code management system](http://git.kernel.org/?p=linux/kernel/git/torvalds/linux-2.6.git;a=summary) of the main development branch and in the first release candidate of 2.6.27. We have previously discussed some of the changes in previous editions of the kernel log â€“ for example the first steps towards removing the Big Kernel Lock (BKL), the new procedures for firmware or [the inclusion of the gscpa and iwl-5000 webcam and WLAN drivers](../site/news/item/Kernel-Log-Centrino-2-WiFi-driver-iwl-5000-and-webcam-driver-gscpa-in-Linux-2-6-27-736569.html "Kernel Log: Centrino 2 WiFi driver iwl 5000 and webcam driver gscpa in Linux 2.6.27 â 23 July 2008, 16:46"). In the last few days, Torvalds and his fellow developers have integrated many other changes.

Major changes were made to the infrastructure surrounding the system standby states. These changes allow drivers to carry out different tasks when changing into or out of ACPI S3/Suspend to RAM than before or after a Hibernate/Suspend to Disk and are intended to alleviate some of the general problems with standby states. As already mentioned in the heise open article "[In-depth insights â€“ Linux information from the OLS](../site/open/features/In-depth-insights-Linux-information-from-the-OLS-746494.html "In-depth insights – Linux information from the OLS â 31 July 2008, 12:43")", the presentation titled [*Suspend-to-RAM in Linux - State of the Union Address*](http://ols.fedoraproject.org/OLS/Reprints-2008/brown-reprint.pdf) gives into detail about these changes.

The "block layer data integrity support" newly integrated into 2.6.27 ([commit](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=7ba1ba12eeef0aa7113beb16410ef8b7c748e18b), [documentation](http://git.kernel.org/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=c1c72b59941e2f5aad4b02609d7ee7b121734b8d), [background article](http://lwn.net/Articles/290141/)) is also explained in detail in [one](http://ols.fedoraproject.org/OLS/Reprints-2008/petersen-reprint.pdf) of the [OLS presentations](../site/open/features/In-depth-insights-Linux-information-from-the-OLS-746494.html "In-depth insights – Linux information from the OLS â 31 July 2008, 12:43") â€“ this technology is to allow storage controllers for servers with suitable drivers to improve their verification of whether the data has arrived correctly on the storage medium. For the first time, the Ext4 file system can now also handle delayed allocations [1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=64769240bd07f446f83660bb143bb609d8ab4910), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=d2a1763791a634e315ec926b62829c1e88842c86)). This is said to improve performance and minimise data fragmentation; a detailed description of this topic can again be found in [one](http://ols.fedoraproject.org/OLS/Reprints-2008/kumar-reprint.pdf) of the [OLS presentations](../site/open/features/In-depth-insights-Linux-information-from-the-OLS-746494.html "In-depth insights – Linux information from the OLS â 31 July 2008, 12:43"). However, the successor of Ext3 continues to be classified as a development file system not suitable for productive use.

2.6.27 will be the first version to offer the [Ubifs](http://www.linux-mtd.infradead.org/doc/ubifs.html) ([commit](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=1e51764a3c2ac05a23a22b2a95ddee4d9bffb16d), [documentation](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=e56a99d5a42dcb91e622ae7a0289d8fb2ddabffb), [background article](http://lwn.net/Articles/276025/)) file system based on UBI (Unsorted Block Images) and intended for flash storage media without wear levelling. Also new are the [mmu notifiers](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=cddb8a5c14aa89810b40495d94d3d2a0faee6619), which are particularly interesting for virtualisation solutions like KVM, and the [Tracehooks](http://thread.gmane.org/gmane.linux.kernel/707950/focus%3D709648) tracing infrastructure planned as a future basis for [Utrace](http://people.redhat.com/roland/utrace/), which has been vying for inclusion into the kernel for a long time.

2.6.27 will offer the [atl1e](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=a6a5325239c20202e18e21e94291bccc659fbf9e) driver for the Atheros AR8121, AR8113 and AR8114 gigabit LAN chips frequently found, for example, in the latest Asus hardware. In addition, a [large patch](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=34f80b04f325078ff21123579343d99756ad8d0e) provides support for Broadcom's BCM57711 and BCM57711E LAN chips in the bnx2x driver. Also incorporated were the infrastructure and the HFC driver of the [mISDN project](http://www.misdn.org). In the long term, the project's code is to replace the kernel's current ISDN infrastructure. However, there is [controversy](http://thread.gmane.org/gmane.linux.kernel/712411/) around the integration of the mISDN patches because it is unclear whether the changes have been sufficiently examined by kernel developers not involved in mISDN; in addition, the patches did not spend the customary few weeks in linux-next before being integrated. Therefore, we cannot completely rule out that mISDN may temporarily be excluded again only to be re-introduced with 2.6.28.

After several years of development, the lockless pagecache patches by Novell developer Nick Piggin have finally found their way into the main development branch ([1](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=e286781d5f2e9c846e012a39653a166e9d31777d), [2](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=a60637c85893e7191faaafa6a72e197c24386727), [3](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=19fd6231279be3c3bdd02ed99f9b0eb195978064)); these patches speed up certain processes in the memory subsystem, which is said to be particularly beneficial for the performance of large systems. In addition, several changes mainly contributed by SGI developers are intended to allow Linux to operate smoothly on systems with more than 4000Â CPUs. The newly integrated support for the gigabyte pages of recent Opteron CPUs is also likely to be of primary interest for large systems with HPC or database applications.

In his e-mail concerning the [release of 2.6.27-rc1](http://thread.gmane.org/gmane.linux.kernel/713115), Linus Torvalds comments that the number of changes since 2.6.26 is considerably higher than with the previous 2.6.26-rc1, noting that the volume is similar to that of the first pre-release versions of 2.6.24 and 2.6.25. Torvalds says he is nervous about this flood of changes and wonders if too many changes find their way into the kernel in each development cycle. However, he doesn't elaborate on the subject and suggests to discuss it at another event â€“ probably hinting at this year's [Kernel Summit](https://www.linuxfoundation.org/events/kernel) being held in Portland in September.

As in the previous few weeks, Torvalds uses [Git](http://git.or.cz/) to provide some statistics in his [release e-mail](http://thread.gmane.org/gmane.linux.kernel/713115) â€“ according to his figures, just over 50Â per cent of the changes were made in the driver directory. The architecture directory was next with 25Â per cent â€“ this was probably predominantly caused by a [large patch](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=917f0af9e5a9ceecf9e72537fabb501254ba321d) which removed the arch/ppc/ directory.
