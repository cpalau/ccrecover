# Kernel Log: New kernel versions, progress with Btrfs and Tux3

**Dj Walker-Morgan**

![](../site/imgs/43/3/6/5/7/7/3/93e8ea3d0acdf147.jpg) After the release of kernel version [2.6.27.7](http://thread.gmane.org/gmane.linux.kernel/760108) in the second half of November, the maintainers of the stable kernel series recently released version [2.6.27.8](http://thread.gmane.org/gmane.linux.kernel/765972). Both versions contain a fix for a security vulnerability, while in 2.6.27.8 more than a hundred other changes offer small improvements and correct flaws, like the cosmetic improvement to fix the "[dirty feet](http://git.kernel.org/?p=linux/kernel/git/stable/linux-2.6.27.y.git;a=commit;h=79aeb30b95d817f11b125d1bd495d5d3c18bde7d)" of the penguins displayed when booting the framebuffer console.

Version 2.6.27.9 is already [in preparation](http://thread.gmane.org/gmane.linux.kernel/767936) and offers more than eighty additional improvements – among them another [security correction](http://thread.gmane.org/gmane.linux.kernel/767957) and a whole bunch of workarounds for the audio hardware in recent PCs, notebooks and mainboards. The deadline for submitting comments about the changes scheduled for 2.6.27.9 is on Saturday evening; shortly afterwards, Greg Kroah-Hartman is expected to release the next version of the 2.6.27 series.

Thursday's release of the eighth pre-release version of 2.6.28 signals the impending completion of the next major kernel update. Due to the holidays at the end of the year, Linus Torvalds has asked the other kernel developers for their opinion about the release date in [the release email for 2.6.28-rc8](http://thread.gmane.org/gmane.linux.kernel/767677) – if 2.6.28 were released in a couple of weeks, a major part of the merge window for 2.6.29 would be within the holidays, during which time even kernel developers don't necessarily want to sit at their keyboards. It remains to be seen which of Torvalds' suggestions will be adopted; however, he definitely wants to close the two week merge window [before the start](http://thread.gmane.org/gmane.linux.kernel/767677/focus%3D768208) of the [LCA/linux.conf.au](http://linux.conf.au/home) 2009, which opens its doors on 19th January.

Willy Tarreau has [released version 2.4.37](http://thread.gmane.org/gmane.linux.kernel/764122) for the users of series 2.4 kernels. Apart from corrections, it also offers new and updated drivers. In his release notes, Tarreau particularly points out the drivers for storage hardware and for AMD's Geode LX. Some users have requested updated or new network drivers, and the maintainer of series 2.4 is considering the integration of such drivers.

**File systems**

Chris Mason is preparing the integration of Btrfs into the main development branch and has [created](http://thread.gmane.org/gmane.comp.file-systems.btrfs/1601) a Git tree to incorporate the new file system into Linux-next. [Mason hopes](http://thread.gmane.org/gmane.comp.file-systems.btrfs/1601/focus%3D1698) that future versions of Btrfs will be able to handle the on-disk format generated by the code of the recently updated Git tree – this would save Btrfs testers the trouble of having to reformat their storage media for new Btrfs versions on a regular basis. Andrew Morton pointed out that the code still needs to be reviewed before it is incorporated into Linux-next; Mason has listed several [known problems](http://thread.gmane.org/gmane.comp.file-systems.btrfs/1601/focus%3D1708) related to this process.

Daniel Phillips has been entertaining the users and developers interested in the still very young Tux3 file system with emails containing detailed progress information ([1](http://thread.gmane.org/gmane.linux.kernel/762135), [2](http://thread.gmane.org/gmane.linux.file-systems/27746), [3](http://thread.gmane.org/gmane.linux.file-systems/27963)). Although it is also experimental, Btrfs is already much more advanced than Tux3 and offers a considerably wider range of features; nevertheless, Andrew Morton has already advised Phillips to stop developing new features for Tux3 as soon as possible and submit the file system to the kernel developers for integration.

**Kernel log in brief**

- AMD has released version 8.12 of its proprietary Linux graphics drivers for [x86-32](http://ati.amd.com/support/drivers/linux/linux-radeon.html) and [x86-64](http://ati.amd.com/support/drivers/linux64/linux64-radeon.html) systems. The [release notes](http://www2.ati.com/drivers/linux/catalyst_812_linux.pdf)![PDF](../site/icons/file-pdf.gif "PDF document") list several of the improvements, for example the support of Ubuntu 8.10 and stream computing – the latter is also one of the new features of the simultaneously released Windows driver.

<!-- -->

- The [X.org](http://x.org) developers are focussing on the development of version 1.6 of the X server and have released their [third beta](http://lists.freedesktop.org/archives/xorg-announce/2008-December/000705.html). The X.org hackers also released [synaptics 0.99.2](http://lists.freedesktop.org/archives/xorg-announce/2008-December/000704.html), [dri2proto 1.99.3](http://lists.freedesktop.org/archives/xorg-announce/2008-December/000700.html), and [libXrandr 1.2.91](http://lists.freedesktop.org/archives/xorg-announce/2008-December/000698.html).

<!-- -->

- The kernel hackers responsible for the [real-time tree](http://rt.wiki.kernel.org/) have recently started a [Git tree](http://thread.gmane.org/gmane.linux.rt.user/3697/) designed, to prepare the improvements developed in the RT tree for integration into the main development branch of Linux.

<!-- -->

- Kristian Høgsberg has written two blog entries to discuss the progress of the [lightweight Wayland X server](../site/news/item/New-Wayland-X-server-looks-to-how-a-modern-desktop-works-737993.html "New Wayland X server looks to how a modern desktop works – 06 November 2008, 09:31") ([1](http://hoegsberg.blogspot.com/2008/12/wayland-gets-terminal.html), [2](http://hoegsberg.blogspot.com/2008/12/two-x-servers-and-microphone.html)).

<!-- -->

- Thomas Gleixner and Ingo Molnar released the first version of the [*Performance Counters for Linux*](http://thread.gmane.org/gmane.linux.kernel.cross-arch/2578/) performance monitoring infrastructure a few days ago, and supplied two updated versions shortly afterwards ([1](http://thread.gmane.org/gmane.linux.kernel.cross-arch/2631/), [2](http://thread.gmane.org/gmane.linux.kernel/767846/)). This caused quite a bit of discussion on the Linux Kernel Mailing List (LKML), as many kernel hackers had expected the integration of the, more mature, but also more complex perfmon3, in the near future.

<!-- -->

- [In his blog](http://who-t.blogspot.com/2008/12/evdev-xorgconf-hal-and-other-fud.html), Peter Hutterer tries to disperse several myths surrounding evdev, xorg.conf and hal. The blog entry was triggered by [a long discussion](http://lists.freedesktop.org/archives/xorg/2008-November/040832.html) about the use of X without [HAL](http://freedesktop.org/wiki/Software/hal) on the X.org developer mailing list.

<!-- -->

- Kernel hacker Matthew Garrett, who often deals with ACPI and power saving topics, has developed an educational interest and summarised several "good practices" for saving power under Linux [in a document](http://www.codon.org.uk/~mjg59/power/good_practices.html). He explains that the ondemand governor usually enabled by default represents the best choice for modern processors; in contrast to what is implied by their names, the powersave and performance governors don't improve power saving and performance, he said.
