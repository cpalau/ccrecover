# Kernel Log: Coming in 2.6.33 (Part 4) - Architecture and virtualisation

**Chris von Eitzen**

#### ![Kernel Log Logo](../site/imgs/43/4/8/0/9/5/6/KL.jpg-1f663d67fe8a53b0.jpeg) by Thorsten Leemhuis

**Several changes to the X86 and KVM code are to speed up the kernel's own hypervisor. The kernel developers once again revised and considerably extended the still emerging tracing infrastructure. The Power and PowerPC code now also supports the Gamecube and Wii games consoles.**

When releasing Linux 2.6.33-rc7 at the end of last week, [Linus Torvalds expressed some dissatisfaction](http://thread.gmane.org/gmane.linux.kernel/947300) because the main development branch currently contains more flaws than he would like. He asked the developers to take another close look at the list of [known bugs in the predecessor of 2.6.33](http://article.gmane.org/gmane.linux.kernel.wireless.general/46197) and indicated that he will probably release an eighth RC before finalising Linux 2.6.33.

The Kernel Log takes this opportunity to continue its report about the advancements of Linux 2.6.33, discussing what's new in terms of architecture support, kernel infrastructure, tracing and virtualisation in the following fourth part of the "Coming in 2.6.33" mini series. The [first](../site/news/item/Kernel-Log-Coming-in-2-6-33-Part-1-Networking-898841.html "Kernel Log: Coming in 2.6.33 (Part 1) - Networking – 08 January 2010, 11:01"), [second](../site/news/item/Kernel-Log-Coming-in-2-6-33-Part-2-Storage-914669.html "Kernel Log: Coming in 2.6.33 (Part 2) - Storage – 27 January 2010, 18:01") and [third](../site/news/item/Kernel-Log-Coming-in-2-6-33-Part-3-Graphics-922495.html "Kernel Log: Coming in 2.6.33 (Part 3) - Graphics – 05 February 2010, 14:14") part of this series covered the most important changes concerning network support, file systems, the storage subsystem and graphics hardware.

### Virtualisation

[Numerous improvements](http://thread.gmane.org/gmane.comp.emulators.kvm.devel/43718) have been made to the KVM (Kernel-based Virtual Machine) virtualisation solution, which is mainly developed by Red Hat. Some of these, for instance, have improved the kernel hypervisor's interaction with the Cpufreq framework responsible for changing the clock speed of modern processors. Various other changes to the KVM code, in combination with [X86 code modifications](http://thread.gmane.org/gmane.linux.kernel/922178), are to reduce the management effort required for context switches, which is designed to improve performance ([1](http://git.kernel.org/linus/26bb0981b3ff00b9177d61fe55806db978862b3c), [2](http://git.kernel.org/linus/18863bdd60f895f3b3ba16b15e8331aee781e8ec)). KVM no longer blocks the virtualisation functions of modern CPUs [unless it actually needs them](http://git.kernel.org/linus/10474ae8945ce08622fd1f3464e55bd817bf2376); this allows other virtualisation solutions to work without first having to unload the KVM's kernel modules when KVM is inactive. The KVM developers also [improved](http://git.kernel.org/linus/ffde22ac53b6d6b1d7206f1172176a667eead778) the operation of paravirtualised Xen guest systems under Xen. Furthermore, the kernel can now shift memory areas that have been merged by the KSM (Kernel Shared Memory) feature, which was created in the KVM area and [introduced in Linux 2.6.32](../site/news/item/Kernel-Log-Coming-in-2-6-32-Part-5-Architecture-code-memory-management-virtualisation-and-tracing-870357.html "Kernel Log: Coming in 2.6.32 (Part 5) - Architecture code, memory management, virtualisation and tracing – 27 November 2009, 10:10"), [into swap memory](http://git.kernel.org/linus/5ad6468801d28c4d4ac9f48ec19297817c915f6a) if required.

Mainly developed by Novell, the KVM-related [AlacrityVM](http://developer.novell.com/wiki/index.php/AlacrityVM) hypervisor, designed specifically for High Performance Computing (HPC) and real-time applications, was submitted for inclusion in 2.6.33 but didn't make it, just like the [distributed Ceph file system](../site/news/item/Kernel-Log-Coming-in-2-6-33-Part-2-Storage-914669.html "Kernel Log: Coming in 2.6.33 (Part 2) - Storage – 27 January 2010, 18:01"). [According to Torvalds](http://thread.gmane.org/gmane.linux.file-systems/37252/focus%3D37411), this was both because of time issues and because too few of the kernel developers and distributors appear to have advocated it; several kernel hackers had previously accused the AlacrityVM developers of [insufficient cooperation](http://thread.gmane.org/gmane.linux.kernel/923880/focus%3D44268) with the developers of the KVM project, sparking [protracted discussions](http://thread.gmane.org/gmane.linux.kernel/923880/); an article on LWN.net [summarises](http://lwn.net/Articles/367787/) the respective background information.

### Tracing

The developers have made further changes to the tracing infrastructure around Ftrace and to the performance events previously called performance counters ([1](http://thread.gmane.org/gmane.linux.kernel/922115), [2](http://thread.gmane.org/gmane.linux.kernel/922151), [3](http://thread.gmane.org/gmane.linux.kernel/928494)). The new "[kprobe-based event tracer](http://git.kernel.org/linus/413d37d1eb69c1765b9ace0a612dac9b6c990e66)" allows probe points to be added to almost any kernel area at run-time ([documentation](http://git.kernel.org/linus/d8ec91850efaf6cee9234c80260fe03881242374)); users can access this infrastructure via the "perf" program, which is included in Linux and offers a [new "probe" subcommand](http://git.kernel.org/linus/4ea42b181434bfc6a0a18d32214130a242d489bf). Details of a previous developer version of the now added code can be found in an [article released](http://lwn.net/Articles/343766/) on LWN.net last summer. LWN.net also offers three articles by Steven Rostedt describing the Linux kernel's tracing options, which he co-developed – the [most recent of them](http://lwn.net/Articles/370423/) was released in January and explains several advanced uses of the tracing infrastructure, but it also contains references to two earlier articles describing the basics.

Several kernel changes allow processes to be [monitored simultaneously](http://git.kernel.org/linus/756d17ee7ee4fbc8238bdf97100af63e6ac441ef) or improve [Big Kernel Lock (BKL) diagnostics](http://git.kernel.org/linus/96a2c464de07d7c72988db851c029b204fc59108). The analysed data can now be filtered via [regular expressions](http://git.kernel.org/linus/1889d20922d14a97b2099fa4d47587217c0ba48b); the kernel developers have also extended the Perf command's Perl script support (for example [1](http://git.kernel.org/?p=linux/kernel/git/torvalds/linux-2.6.git&a=commitdiff&h=16c632de64a74644a46e7636db26b2cfb530ca13), [2](http://git.kernel.org/linus/bcefe12eff5dca6fdfa94ed85e5bee66380d5cd9), [3](http://git.kernel.org/linus/d1b93772be78486397693fc39d3ddea3fda90105), [documentation](http://git.kernel.org/linus/89fbf0b8a021cbf60abeacfb6b538e97c83afada)). Its "bench" subcommand, which is new in 2.6.33, offers several speed measuring functions (for example [1](http://git.kernel.org/linus/629cc356653719c206a05f4dee5c5e242edb6546) [2](http://git.kernel.org/linus/c7d9300f367f480aee4663a0e3695c5b48859a1a), [3](http://git.kernel.org/linus/827f3b4974c5db2968d4979fe6a0ae00ab37bdd8), [4](http://git.kernel.org/linus/e27454cc6352c4226ddc76f5e3a5dedd7dff456a), [documentation](http://git.kernel.org/linus/9fbc04f2493929a69fd9e53b5fb53c127d7950d5)).

New are also Perf's "[kmem](http://git.kernel.org/linus/ba77c9e11111a172c9e8687fe16a6a173a61916f)" and "[diff](http://git.kernel.org/linus/86a9eee047ba09a714c3b8e27c9df2bbf715393a)" subcommands as well as [kernel module support](http://git.kernel.org/linus/439d473b4777de510e1322168ac6f2f377ecd5bc) improvements.

### Linux on the Gamecube and Wii

The architecture code for Power and PowerPC CPUs now supports Nintendo's GameCube and Wii games consoles (for example [1](http://git.kernel.org/linus/e90d71d0f52fb3d619b96ba92b7614fed7cb819e), [2](http://git.kernel.org/linus/5a7ee3198dfade8eaea260399fd168e4e9c1a3a9)); further details can be found on the [GC Linux](http://gc-linux.sourceforge.net/) project's web page, and via the commit links at the end of this article.

ARM, MIPS and x86 systems now allow the kernel and initial ramdisk (initrd) to be compressed via LZO; the commit comment states that, while LZO doesn't compress as efficiently as Gzip, it can be decompressed considerably faster on ARM systems ([1](http://git.kernel.org/linus/7dd65feb6c603e13eba501c34c662259ab38e70e), [2](http://git.kernel.org/linus/cacb246f8db2b9eba89d44a0f0dd4f6ed93bc113), [3](http://git.kernel.org/linus/13510997d600a076e064f10587a8f6d20f8fff41), [4](http://git.kernel.org/linus/e7db7b4270ed2a606b8c0b5f944a5f92ade0e84c), [5](http://git.kernel.org/linus/fe1d45e08650213ec83a72d3499c3dd703243792)). The ARM developers have integrated a large number of further improvements for dozens of different systems with ARM CPUs or ARM cores; [one new addition](http://git.kernel.org/linus/edabd38e1a017e922e3e3b485ee3ddb4df433aa4), for example, supports the Dove (88AP510) SOC (System-on-a-Chip) made by Marvell. Not only the code for ARM hardware, but also that for other architectures has been extended to support new processors and systems even die-hard Linux fans may not have heard about – the MIPS code, for instance, will from now on [support](http://git.kernel.org/linus/a3a0f8c8ed2e2470f4dcd6da95020d41fed84747) Cisco's MIPS 24Kc-based "Powertv cable settop box". Also new is the code to support the [Loongson 2F](http://git.kernel.org/linus/6f7a251a259e5bf58a9ff334bdcfa3e42b6cb7a3).

The real-time developers made numerous changes to further reduce the use of the Big Kernel Lock (BKL). Currently inconsequential for users is a [major renaming](http://thread.gmane.org/gmane.linux.kernel/927617) of the spinlocks used for locking critical internal kernel areas. These locking mechanisms, which work with active waiting and must not be interrupted, are now called arch_spinlock_t. The restructuring measures make the Linux real-time developers' job a lot easier and forms the basis for moving the "[sleeping spinlocks](http://lwn.net/Articles/271817/)" from the [Realtime/RT tree](http://rt.wiki.kernel.org/) into the official Linux kernel. They also make it possible to interrupt the majority of the spinlocks that have so far used active waiting to gain exclusive access to shared data structures in the fastest possible way – this is the last major component for proper real-time functionality still missing in the official Linux kernel. Details about the renaming measures can be found in a [short message on LWN.net](http://lwn.net/Articles/365863/); two older articles provide more information about sleeping spinlocks and the RT tree's current state of development ([1](http://lwn.net/Articles/357800/), [2](http://lwn.net/Articles/354690/)).

### ACPI, PCI and power management

In future, Sysfs files [will show](http://git.kernel.org/linus/e2f74f355e9e2914483db10c05d70e69e0b7ae04) whether the BIOS is using ACPI to block the switch to maximum CPU frequency in certain device modes. Furthermore, Rafael J. Wysocki [had submitted](http://thread.gmane.org/gmane.linux.acpi.devel/43304/) several patches that in certain devices make the kernel suspend or resume in parallel instead of sequentially when switching into or out of standby. This is intended to [speed up](http://thread.gmane.org/gmane.linux.acpi.devel/43304/) suspending and resuming. Linus Torvalds, however, rejected the changes [rather unequivocally](http://thread.gmane.org/gmane.linux.acpi.devel/43304/focus%3D43305); details about this and the patches can be found in an [article on LWN.net](http://lwn.net/Articles/366915/). As a result, Wysocki has put the changes on hold and [submitted](http://thread.gmane.org/gmane.linux.kernel/923153) several patches which, for instance, offer run-time improvements to the power saving infrastructure for I/O devices, which was reworked in 2.6.32. However, Wysocki has since [readjusted](http://thread.gmane.org/gmane.linux.acpi.devel/44581) the "asynchronous suspend and resume" code and is likely to resubmit it for 2.6.34.

### In brief

- Mostly [minor changes](http://thread.gmane.org/gmane.linux.kernel/922153) have been made to the scheduler this time round.
- Introduced in 2.6.32, [HWPOISON](../site/news/item/Kernel-Log-Coming-in-2-6-32-Part-5-Architecture-code-memory-management-virtualisation-and-tracing-870357.html "Kernel Log: Coming in 2.6.32 (Part 5) - Architecture code, memory management, virtualisation and tracing – 27 November 2009, 10:10") received [bux fixes and several improvements](http://thread.gmane.org/gmane.linux.kernel/927007).
- Linux Security Modules (LSM), which is used by the kernel by default, can from now on be [enabled](http://git.kernel.org/linus/6e65f92ff0d6f18580737321718d09035085a3fb) during kernel configuration.
- SELinux now [dynamically discovers class and permission values upon policy load](http://git.kernel.org/linus/c6d3aaa4e35c71a32a86ececacd4eea7ecfc316c) ("*Modify SELinux to dynamically discover class and permission values upon policy load \[...\]*").
- The [newly added support](http://git.kernel.org/linus/0e1227d356e9b2fe0500d6cc7084f752040a1e0e) for the [PCLMULQDQ instruction](http://software.intel.com/en-us/articles/intel-carry-less-multiplication-instruction-and-its-usage-for-computing-the-gcm-mode/) allows the kernel to delegate certain hash calculation tasks to Intel processors which support this instruction.
