# Kernel Log: Ceph file system in 2.6.34, kernel and KVM presentations at the CLT2010

**Thorsten Leemhuis**

**Linus Torvalds has integrated the Ceph distributed network file system and released the second release candidate of 2.6.34. Torvalds intends to vary the length of the merge window from now on. Slides of the presentations at the Chemnitz Linux Days provide background information about kernel and KVM topics. Ubuntu has been given an AMD graphics driver which cooperates with series 1.7 X Servers.**

When he released the first RC of 2.6.34 early, which [surprised](../site/open/features/Kernel-Log-Linux-2-6-34-goes-into-testing-950563.html "Kernel Log: Linux 2.6.34 goes into testing – 10 March 2010") many subsystem maintainers, Linus Torvalds announced that he might still integrate the Ceph distributed network file system, which [didn't make it into 2.6.33](../site/news/item/Kernel-Log-Linux-2-6-33-enters-test-phase-890581.html "Kernel Log: Linux 2.6.33 enters test phase – 21 December 2009"), although the merge window had already closed. He did this last weekend and, shortly afterwards, released Linux 2.6.24-rc2 – the usual release email for the new version has not so far appeared on the LKML.

![ceph Logo](../site/open/imgs/45/4/9/9/2/5/1/ceph-logo.jpg-f73eda7432e0600c.jpeg) Licensed under the LGPL, Ceph is a "Distributed Network File System" which, [according to the developers](http://ceph.newdream.net/about/), can manage data on a petabyte scale "and beyond", it is robust and offers numerous functions that are missing in other similar open source file systems. Detailed information about Ceph is available on [the project's homepage](http://ceph.newdream.net/), in a [short description](http://git.kernel.org/linus/7ad920b504a980adcab4d3f6b85695526e6fd7bb) which was integrated into the kernel sources together with the file system code, and in [an older article on LWN.net](http://lwn.net/Articles/258516/) which describes an earlier, Fuse-based version of the file system.

The file system wasn't the only major addition Torvalds made after closing the latest merge window two days earlier than usual. Between rc1 and rc2, multiple changes were also made to the Btrfs file system, the SCSI subsystem and the architecture code for ARM, Blackfin and Microblaze CPUs – more than are usually made at this stage, which generally only accommodates a few stragglers. Several days earlier, Torvalds had [actually refused](http://thread.gmane.org/gmane.linux.kernel/959780/focus%3D960766) to integrate the SCSI changes in order to teach the maintainers of the SCSI code and other subsystem maintainers a lesson. Torvalds hoped to prompt them to stop submitting their changes at the last minute, however, it appears that in the end, he did show mercy.

Torvalds has [clarified](http://thread.gmane.org/gmane.linux.kernel/959780/focus%3D960775) that he now intends to vary the length of future merge windows – the period of time in the development cycle in which the majority of changes are integrated into a new kernel version. He said that he won't mention in advance how long the respective merge window is going to be – and that he might close it after seven days if he thinks that there is enough work done. ("*\[...\]I'm not even going to mention in the release notes how long the merge window is going to be. Maybe I'll say "that's enough" after just one week, \[...\]*"). With these measures, Torvalds has further adapted the (partially unwritten) rules of the Linux kernel development process.

### Presentations

In one of the auditoriums the majority of the presentations during the recent [Chemnitz Linux Days](http://chemnitzer.linux-tage.de/2010/) discussed the Linux kernel and its KVM hypervisor. Some of the, mostly German-language, presentation slides and short papers provide ample information for all those who couldn't attend the event:

- For instance, Robert Richter's presentation "[Git is MacGyver - managing kernel sources with Git](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=469)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://www.kernel.org/pub/linux/kernel/people/rric/git-talk-pub.pdf)) explained numerous practical aspects of using Git in kernel development.
- In "[Einführung in das Linux Memory Management (Introduction into Linux memory management)](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=481)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://cmpxchg.org/~hannes/clt10.pdf)), Johannes Weiner provides some background information about the Linux kernel's memory management.
- Stefan Assmann's presentation "[Einführung in Real-Time Linux (Introduction into real-time Linux)](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=517)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://chemnitzer.linux-tage.de/2010/vortraege/shortpaper/517-slides.pdf), [short paper![PDF](../site/icons/file-pdf.gif "PDF document")](http://chemnitzer.linux-tage.de/2010/vortraege/shortpaper/517_preempt-rt.pdf)) explains the significance of real time (RT) and demonstrates how to build a custom real-time kernel.
- Bernhard Walle's [presentation](http://www.bwalle.de/website/clt2010.html) on "[Kernel-Debugging (Kernel debugging)](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=479)" is not just available on [Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://www.bwalle.de/docs/CLT2010/Vortrag.pdf) and as a [short paper![PDF](../site/icons/file-pdf.gif "PDF document")](http://chemnitzer.linux-tage.de/2010/vortraege/shortpaper/479_debugging.pdf), there is also a [text version![PDF](../site/icons/file-pdf.gif "PDF document")](http://www.bwalle.de/docs/CLT2010/Paper.pdf).
- Those who regularly read the Kernel Log at The H Open are unlikely to find many surprises on the [slides](http://bit.ly/ctl10-kernellog)(*direct download*) of the presentation entitled "[Aktuelle Entwicklungen beim Linux-Kernel (Current developments around the Linux kernel)](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=392)", because this presentation was given by the author of the Kernel Log and generally covered topics which have already been discussed.
- The [slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://www.zlug.org/~joro/community-joro.pdf) of Jörg Rödel's presentation entitled "[Patch Applied! - Working with the Linux kernel community](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=463)" offers some important information for all those who want to contribute to the Linux kernel.
- Perhaps rarely significant for desktop systems, but crucial in High Performance Computing (HPC) is the distribution of processes across different cores and processors in multi-processor systems, which is the topic discussed by Andreas Herrmann in "[Why CPU Topology Matters](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=470)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://chemnitzer.linux-tage.de/2010/vortraege/shortpaper/470-slides.pdf)).
- Alexander Graf gave two presentations about KVM: "[KVM on PowerPC](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=474)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://alex.csgraf.de/clt/2010/PowerPC%20KVM.pdf)) and "[Nesting the Virtualized World](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=468)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://alex.csgraf.de/clt/2010/Nested%20SVM.pdf)).
- In "[Live and in Colour - Live Migration?](http://chemnitzer.linux-tage.de/2010/vortraege/detail.html?idx=457)" ([Slides![PDF](../site/icons/file-pdf.gif "PDF document")](http://chemnitzer.linux-tage.de/2010/vortraege/shortpaper/457_folien.pdf)), André Przywara presents some background information on migrating virtual machines between systems without having to suspend the guest system or the server processes running on it.

Some of the many volunteers who organised the Chemnitz Linux Days are currently working to add video and audio recordings of the presentations in the five main auditoriums to the event's homepage. The organisers of the [linux.conf.au (LCA) 2010](http://www.lca2010.org.nz/) held in Wellington, New Zealand, have recently completed this task and have [released](http://2009.r2.co.nz/20100118/) videos of many of the presentations. The kernel and its environment were also a topic there – for example in the "[Kernel Report](http://2009.r2.co.nz/20100118/50141.htm)" by LWN.net founder and figurehead Jonathan Corbet. The slides of many LCA 2010 presentations have been available [via the conference wiki](http://www.lca2010.org.nz/wiki/Talk_Slides) for some time.

### In brief

*Kernel*

- Greg Kroah-Hartman has released the stable kernel versions [2.6.32.10](http://thread.gmane.org/gmane.linux.kernel/961798) and [2.6.33.1](http://thread.gmane.org/gmane.linux.kernel/961799) which, as usual, offer several dozen corrections and minor improvements; the release email contains the [traditional recommendation](../site/open/features/Kernel-Log-Stable-kernels-analysed-Linux-without-firmware-new-graphics-drivers-948051.html "Kernel Log: Stable kernels analysed, Linux without firmware, new graphics drivers – 08 March 2010") that users update to one of these versions.
- Linus Torvalds [refused](http://thread.gmane.org/gmane.linux.kernel/923807/focus%3D964008) to integrate the current form of "writeable limits", which are intended for a future version of SLES and were submitted by Jiri Slaby for integration into 2.6.34.
- Nigel Cunningham has [released](http://thread.gmane.org/gmane.linux.power-management.general/17820) version 3.1 of [TuxOnIce](http://www.tuxonice.net/) – an alternative implementation for using software suspend (suspend/hibernate). At the end of his release email, Cunningham indicates that he intends to focus on improving the kernel's software suspend code once he has completed some remaining TuxOnIce-related tasks.

*Kernel environment ("plumbing layer") and userland drivers*

- Kernel.org administrator John 'Warthog9' Hawley [has announced](http://thread.gmane.org/gmane.linux.kernel/963467) that Kernel.org-hosted services such as Bugzilla, Wiki and Patchwork are now available via SSL.
- Greg Kroah-Hartman has [released](http://thread.gmane.org/gmane.linux.usb.general/29137) version 0.87 of the usbutils.
- Neil Brown has [released](http://thread.gmane.org/gmane.linux.raid/27126) version 3.1.2 of mdadm, whose default metadata format for software RAIDs created via the kernel's MD code is now v1.2.
- In a LWN.net article which is now also [available to non-subscribers](http://lwn.net/Articles/377895/), the Linux Weekly News team have compiled numerous aspects of the interaction between Linux and storage media with 4-KByte sectors. This topic has also been [repeatedly discussed](../site/news/item/Kernel-Log-Linux-and-hard-disks-with-4-KByte-sectors-939523.html "Kernel Log: Linux and hard disks with 4-KByte sectors – 24 February 2010") in the Kernel Log. Furthermore, it recently sparked [prolonged discussions](http://thread.gmane.org/gmane.linux.ide/45211/) on the LKML; the [page in the Linux ATA wiki](https://ata.wiki.kernel.org/index.php/ATA_4_KiB_sector_issues) used by kernel hackers for the relevant background information has [recently](http://thread.gmane.org/gmane.linux.ide/45470) been given another [major overhaul](https://ata.wiki.kernel.org/index.php?title=ATA_4_KiB_sector_issues&diff=1704&oldid=1697); corrections were, for instance, made in some areas that discuss running a Linux distribution in parallel with older Windows versions such as XP.

*Graphics*

- Peter Hutterer has [released](http://thread.gmane.org/gmane.comp.freedesktop.xorg/42905) version 1.7.6 of X.org's X Server, which only introduces minor corrections.
- The latest proprietary Linux graphics drivers on AMD's driver web page don't work with the series 1.7 X Servers that have been available [since last October](../site/news/item/X-org-Server-1-7-0-released-812407.html "X.org Server 1.7.0 released – 02 October 2009"). However, the Ubuntu developers apparently received the [pre-release version](https://launchpad.net/ubuntu/lucid/+source/fglrx-installer/2%3A8.721-0ubuntu1) of a driver that fixes the problem for Ubuntu 10.04, which includes such an X Server. As this driver is not publicly available at AMD, this doesn't really help the users of other distributions with X.org 7.5 X Servers. Ubuntu has received such special treatment for all versions since Ubuntu 8.10, while AMD has, at times, left the users of other distributions out in the cold for months.
- The [beta version](http://www.nvnews.net/vbulletin/showthread.php?p=2212330) of a proprietary NVIDIA driver for GeForce graphics hardware already supports OpenGL 3.3.
- The developers of the ATI X.org driver package have released versions [6.12.6](http://thread.gmane.org/gmane.comp.freedesktop.xorg/42882) and [6.12.192](http://thread.gmane.org/gmane.comp.freedesktop.xorg/42883) of their drivers for Radeon graphics cards; the latter version is the second release candidate of the series 6.13 drivers and is said to considerably improve the performance of KMS EXA DFS (and, therefore, of GetImage).
- Michel Dänzer has [released](http://thread.gmane.org/gmane.comp.freedesktop.xorg.announce/1018) version 11.0.1 of the X.org graphics drivers for VMware guests.
- On the X.org developer mailing list, Peter Hutterer has provided [an overview](http://thread.gmane.org/gmane.comp.freedesktop.xorg.devel/5907) of what he thinks is required for X to provide decent multi-touch support.
- In his blog, Dave Airlie describes [some experiments](http://airlied.livejournal.com/72187.html) that involve running two X Servers on one graphics card – this is interesting for scenarios such as multi-seat environments.
- In a [second post](http://airlied.livejournal.com/71734.html), Airlie explained some aspects of a "proof of concept" in which a Radeon graphics card computes images that are subsequently output via Intel chip-set graphics.
