# Kernel Log: Linux 2.6.25 with Smack security framework, LCA08 online

**Mike Barwise**

![Tux](../site/imgs/43/3/6/0/9/2/6/1ffba677796c44bd.png) In mere under two weeks since Linux 2.6.24 was released, 7931 patches have been incorporated into the Linux kernel development branch maintained by Linus Torvalds, from which Linux 2.6.25 should eventually emerge in about two months time. The Simplified Mandatory Access Control Kernel [(Smack)](http://www.schaufler-ca.com/) security framework [has been added](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=e114e473771c848c3cfec05f0123e70f1cdbdc99) to the new features described in the last Kernel Log. Like SELinux, it offers mandatory access control (MAC), but [deliberately foregoes](http://lwn.net/Articles/244531/) many of the other protective functions offered by SELinux. This is intended to make Smack much easier to handle than SELinux, which has the reputation of being difficult to use.

The development team has definitively removed [a number of OSS sound drivers](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=83bad1d764b836a482b88e0a1f44d7a5c3e1fee0), such as i810_audio and via82cxxx_audio, as the kernel now includes Alsa sound drivers for the same hardware. The MAC80211 WLAN Stack is [no longer](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=03ac7a8141e1613add92d42e389a35a126b1caf8) marked as experimental. Various patches under the banner of maps4 and "Proportional Set Size" [(PSS)](http://git.kernel.org/git/?p=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=ec4dd3eb35759f9fbeb5c1abb01403b2fde64cc9) should in future allow [more precise analysis](http://lwn.net/Articles/230975/) of memory allocated to userspace programs. Torvalds has also incorporated various Virtio patches, including the [balloon driver](http://git.kernel.org/git/?=linux/kernel/git/torvalds/linux-2.6.git;a=commit;h=6b35e40767c6c1ac783330109ae8e0c09ea6bc82), which allows the amount of memory on the guest system to be adjusted at run time.

A few days after the event's conclusion, the organisers of **linux.conf.au** (LCA), which was attended by many Linux programmers, have made audio and video edits of almost all of the talks and many of the presentations [available online](http://linux.conf.au/programme/presentations). You can now watch the opening keynote speech on "Reconceptualizing Security", given by security expert Bruce Schneier, at your leisure without visiting the Southern hemisphere.

The talk entitled "Make hardware vendors love open source", given by Intel's Dirk Hohndel, offered many reasons why some hardware vendors fail to get to grips with the open source concept. Users should also inform hardware vendors when they use Linux instead of Windows on their laptops. Long-established kernel and X developer Dave Airlie also took aim at hardware vendors in his talk "Bringing kittens back to life – continuing story of open source graphics drivers", out of which Nvidia does not come well - the Californian company provides open source programmers with negligible information on driver development. ATI was subjected to similar criticism in a previous version of Airlie's talk, but has since smartened up its act by distributing documentation and even sponsoring development of an open source driver.

Several developments likely to find their way into forthcoming Linux distributions were also described or demonstrated [in talks](http://linux.conf.au/programme/presentations) at LCA08. Jonathan Corbet, founder and executive editor of [LWN.net](http://lwn.net/) delivered an updated version of his familiar talk on kernel development and forthcoming new features in Linux. Veteran X hacker Keith Packard reported on the latest developments with the X server in "Roadmap to recovery: Pain and Redemption in X driver development".

Kernel version **2.6.22.17**, discussed in the last Kernel Log has now [been released](http://thread.gmane.org/gmane.linux.kernel/635468). This should be the last version in the 2.6.22 stable series and fixes the security problems related to [core dumps](http://bugzilla.kernel.org/show_bug.cgi?id=3043) (see: [CVE-2007-6206](http://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2007-6206)) and [mmap](http://lkml.org/lkml/2008/2/6/457). The kernel development team recommends that 2.6.22 users upgrade to the latest version. Kernel version **2.6.23.15** is currently in [preparation](http://thread.gmane.org/gmane.linux.kernel/635582). With 73 patches, it represents a relatively major revision and should be released at the weekend.

**Kernel Log staccato**: Torvalds has [now clarified](http://thread.gmane.org/gmane.linux.kernel/631544/focus%3D634566) why he has chosen not to include the KGDB kernel debugger in version 2.6.25. The GCC development team [is releasing](http://gcc.gnu.org/ml/gcc-announce/2008/msg00000.html) version 4.2.3 of the GNU compiler collection. The [Madwifi Project](http://madwifi.org/) has [joined](http://madwifi.org/wiki/news/20080207/madwifi-org-joins-spi) "Software in the Public Interest" ([SPI](http://www.spi-inc.org/)) and is now able to accept donations from users through SPI. Chris Mason has [released](http://thread.gmane.org/gmane.linux.file-systems/20923) version 0.12 of the experimental Btrfs file system, which is much faster than the previous version in certain Tiobench tests. The Linux Foundation has released the [second part](http://linux-foundation.org/weblogs/openvoices/linus-torvalds-part-ii/) of a very wide-ranging [interview](http://linux-foundation.org/weblogs/openvoices/linus-torvalds-part-i/) with Linus Torvalds.
