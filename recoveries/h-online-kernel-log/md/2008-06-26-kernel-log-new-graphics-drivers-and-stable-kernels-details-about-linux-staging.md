# Kernel log: New graphics drivers and stable kernels; details about Linux-staging

**Terry Relph-Knight**

![Kernel log logo](../site/imgs/43/3/6/3/0/7/6/a345f5e7c547062f.jpg) Numerous new versions for various popular AMD, Nvidia and Intel graphics drivers for Linux were released in the last few days.

AMD released [Catalyst version 8.6](http://ati.amd.com/support/drivers/linux/linux-radeon.html) of the proprietary graphics driver for Radeon GPUs which is also known as fglrx. It fixes several bugs and offers an improved installation routine; in addition, the driver is already said to support the new generation of Radeon graphics chips soon due for release. However, the new version still doesn't support the pre-release versions of X Server 1.5, which is supplied with Fedora and is part of X.org 7.4. Dave Airlie has published [DRM patches](http://thread.gmane.org/gmane.comp.video.dri.devel/30949) for a pre-release version of Linux 2.6.26 which match the micro code to that released by AMD and provide 3D support for R500 GPUs in the kernel's Direct Rendering Manager – to achieve 3D acceleration with the Radeon X1000 series, new versions of the ati or radeonhd X.org drivers and a new Mesa are also required. Linus Torvalds has integrated Airlie's patches in the main development branch currently leading to 2.6.26 although the patches were rather large and the development cycle is already well advanced.

Nvidia has released new versions of its proprietary graphics drivers for Linux [x86-32](http://www.nvidia.com/object/linux_display_ia32_177.13.html) and [x86-64](http://www.nvidia.com/object/linux_display_amd64_177.13.html); these drivers also contain corrections (for example for X Server 1.5) and support the latest GPU generation which was introduced only recently. The code in the main development branch of the "nv" X.org driver for Nvidia cards has recently [started to support](http://gitweb.freedesktop.org/?p=xorg/driver/xf86-video-nv.git;a=commitdiff;h=2df11aafe4eae33aab06d902ddeed6bd996b1575) this GPU generation and is also said to co-operate with [many](http://gitweb.freedesktop.org/?p=xorg/driver/xf86-video-nv.git;a=commitdiff;h=745a1d2d318eef0a6195fe08e4a43471b6d0a662) series 9 GeForce Mobile chips. Following a statement [against proprietary Linux kernel drivers](../site/news/item/Linux-kernel-developers-speak-out-against-proprietary-drivers-735575.html "Linux kernel developers speak out against proprietary drivers – 24 June 2008, 11:04") by many important kernel developers yesterday, [Nvidia has defended its decision in a statement](http://blogs.zdnet.com/open-source/?p=2588) on ZDNet; According to the ZDNet blog, the vendor doesn't plan to release any open source graphics drivers in the future and claims that there is no need for them.

Intel developers have now released [version 2.3.2 of their open source drivers](http://lists.freedesktop.org/archives/xorg-announce/2008-June/000589.html) for X.org, which mainly fixes bugs. The programmers are already working on driver generation 2.4 to integrate HDMI and DisplayPort support. The next generation of drivers is said to support G45 chip sets and use the recent [GEM](../site/news/item/Kernel-Log-Linux-staging-branch-will-help-with-integration-Linux-kernel-2-6-25-6-and-2-6-26-rc6-735507.html "Kernel Log: Linux-staging branch will help with integration; Linux kernel 2.6.25.6 and 2.6.26-rc6 – 17 June 2008, 11:31") for memory management.

Since the last kernel log, the maintainers of the Linux Stable Series have released Linux versions [2.6.25.7](http://thread.gmane.org/gmane.linux.kernel/694638) and [2.6.25.8](http://thread.gmane.org/gmane.linux.kernel/696498). Both versions fix various kernel bugs and improve the hardware support in a few drivers; the kernel developers did not make any explicit security-related corrections. With version 2.6.25.9, the next version of the 2.6.25 series is already scheduled for release today or tomorrow; in its current incarnation it contains ten changes to fix further bugs (see [1](http://thread.gmane.org/gmane.linux.kernel/696623), [2](http://thread.gmane.org/gmane.linux.kernel/697210)).

Following the release of [pre-release version seven](http://thread.gmane.org/gmane.linux.kernel/696275) a few days ago, the development of Linux 2.6.26 is now in its final stages; however, looking at the [error list](http://thread.gmane.org/gmane.linux.kernel/696621), various error reports on the LKML and some recent changes to the main development branch it is possible that there will be an eighth pre-release version. It is unlikely, however, that the next Linux version released by Linus Torvalds will take more than another two weeks to complete.

After introducing the Linux-staging development branch and following further discussions and considerations, Greg Kroah-Hartman has announced that [Linux-staging will not be contained in Linux-Next](http://thread.gmane.org/gmane.linux.kernel.next/738/focus%3D696319) as originally planned. Instead, he now plans to maintain the branch separately and update patches with every RC version in the Quilt tree managed with Git. For every pre-release version and for the final kernels in the main development branch, Kroah-Hartman also plans to combine the patches in the Quilt tree into one big patch to make integrating Linux-staging easier for testers. He recently [released the first of these patches](http://thread.gmane.org/gmane.linux.kernel/696332) for Linux 2.6.26-rc7.

The introduction of Linux-staging was triggered by discussions about the optimum timing for integrating new drivers. James Bottomley recently [picked up this thread](http://thread.gmane.org/gmane.linux.kernel/695294/) and suggested a detailed discussion at this year's Kernel Summit.

**Kernel log in brief**:

- [Matthew Garrett has published the source code of an experimental kernel module](http://mjg59.livejournal.com/91888.html) that tries to re-initialise Nvidia graphics hardware after a suspend. This is said to enhance the interoperability with the open source "nv" X.org driver in ACPI S3 mode – so far, this mode has been unreliable, or not functioned at all, in connection with the free X.org driver.
- The current developers of Git, the source code management system started by Linus Torvalds and used extensively in the Linux kernel environment, have released [version 1.5.6](http://thread.gmane.org/gmane.comp.version-control.git/85423).
- Michael Kerrisk has become a [fellow](http://en.wikipedia.org/wiki/Fellow) with the Linux Foundation and will work on various documentation projects. In this position he has already [released man-pages 3.0](http://thread.gmane.org/gmane.linux.kernel/694796). In the future he intends to handle API descriptions and maintain the [documentation shipped with kernels](http://thread.gmane.org/gmane.linux.kernel/694797).
- Jouni Malinen has [published a patch that integrates support](http://thread.gmane.org/gmane.linux.kernel.wireless.general/16374) for the not yet finalised IEEE 802.11w (Protected Management Frames) into the MAC80211 Linux wireless stack.
- The developers of the Hplip project have [released version 2.8.6 of the Hplip drivers](http://hplip.sourceforge.net/release_notes.html) for HP printers and multifunctional devices. This version is the first to support 30 new devices – including numerous all-in-one models.
- Olaf Kirch has started to [work on a new document describing the most important internal aspects of the network stack](http://thread.gmane.org/gmane.linux.network/96886), which will allow newcomers to approach the subject without being overwhelmed by details.
- The developers of the LessWatts initiative have [released PowerTop version 1.10](http://www.bughost.org/pipermail/power/2008-June/001384.html).
